# 联邦与防护：先 Git，后链

> 状态：**已确认路线，分层实现中** · 2026-10-26
> 关联：[00-SPEC.md](00-SPEC.md) 规则 7/8 · [03-共享森林框架.md](03-共享森林框架.md) 证据阶梯

---

## 0. 一句话

**先让一棵树可以安全地离开本机，再谈让森林彼此连接。**
Git 足够做发布、签名、订阅和撤回；区块链以后只补"全局身份与时间锚"，不拿来存知识。

---

## 1. 什么是 Git 联邦

不是新协议，就是把每台机器上的 Trees 仓库当成一个**节点**：

| Git 概念 | 在 Trees 里对应 |
|---|---|
| 仓库 | 一个节点（一个人 / 一台机器 / 一个组织） |
| commit | 一次可审计的变更事件 |
| commit 签名（GPG / SSH） | **密钥指纹 = 身份**，作者不可抵赖 |
| 远程仓库 / 订阅源 | 你选择信任的上游 |
| `git pull` | 同步：只拉你订阅的源 |
| `git push` | 发布：只推你选择发布的树 |
| fork | 分叉：意见不合时各长各的，不互相删除 |
| tag / release | 快照：某一时刻的森林状态 |
| `manifest.json` + sha256 | 内容寻址：订阅方逐文件校验 |
| 墓碑提交 | 撤回：删除内容，但保留"曾存在且已撤回"的记录 |

**核心：所有内容仍然是 Markdown + Git，没有服务器、没有账号、没有锁定。**

### Git 能做的防护（现在就能加）

- 只发布选中的树（默认私有）
- 每个文件 sha256，篡改立刻可见
- 提交签名，作者可追溯
- 订阅白名单，不 pull 不信任的源
- 导入隔离区，人工/规则审查后才进主库
- 撤回 = 新提交 + 墓碑，历史可查

### Git 做不到的（留给链或其它机制）

- 全局唯一身份（同一个人可以有多个 Git 身份）
- 抗 Sybil（小号批量提交是免费的）
- 全局发现（没有中心索引，只能靠订阅源）
- 不可篡改的全局时间顺序
- 跨节点的自动结算

> 注意：**区块链也不是 Sybil 的解药**。没有成本、身份或信誉约束，链上一样可以刷。
> 链解决的是"全局可验证的登记与锚定"，不是"什么是真的"。

## 2. 威胁 → 现在的防护

| 失败模式 | Git 联邦阶段能做的 | 还不能做的 |
|---|---|---|
| 洗稿 / 改标点刷树 | 归一化 + 精确哈希；发布包带 sha256 | AI 语义判重（下一步） |
| 重复导入 | 按内容哈希去重 | 跨节点全局去重 |
| 恶意种子 | **默认私有 + 只发布选中树**；导入隔离区 | 自动内容审核 |
| 提示注入 | 导入文本一律当**数据**，不执行；召回时标来源 | 模型级指令隔离 |
| 冒充作者 | commit 签名 + manifest 里记 planter | 全局身份绑定 |
| 垃圾洪泛 | 发布包大小/种子数上限；白名单订阅 | 全网反垃圾 |
| 撤回追不到副本 | 墓碑 + 血缘字段；订阅方按 manifest 校验 | 强制全网撤回 |
| 违法/侵权内容 | 不发布、可下架、保留墓碑 | 跨节点强制删除 |

**硬规则：核心永不自动执行、永不自动导入、永不联网。** 所有网络动作都由人显式触发。

## 3. 选择性发布（已实现）

```
trees share <tree-id>
```

- 只打包**这一棵树**和它挂着的种子；库里其他种子一概不进包
- 树和种子标 `visibility: shared`；默认是 `private`
- 会话树拒绝发布（原料不是结果）
- 产出 `forest/publish/<tree-id>/`：
  - `<tree-id>.md`
  - `seed-XXXX.md` × N
  - `manifest.json`（每个文件的 sha256、树牌、血缘、证据等级）
  - `PUBLISH.md`（订阅方核对步骤）
- 不联网、不删除、不改其他树

订阅方流程（下一步实现）：

```
git clone/pull → 校验 manifest 每个 sha256 → 放进 quarantine/
→ 人工或规则审查 → 才 merge 进 forest/
```

## 4. 搭建顺序

每一步都有明确的验收物，不跳步。

### Stage 1 — 查重（已实现）

- 归一化：NFKC、全半角、零宽字符、标点、大小写
- 精确哈希 → 中文二字组 / 英文词 Jaccard → AI 判 `same/subset/overlap/different`
- 播种时：精确重复直接复用已有种子（挂到当前树），不新建；近重复提示
- 命令：`trees dedup [--threshold 0.7] [--ai] [--json]`
- 验收：真实库 8 颗无重复；测试覆盖零宽/全角、精确分组、近重复、AI 判定

### Stage 2 — 证据阶梯

- 字段已有：`evidence_level` / `external_ids` / `retracted` / `conjecture_status` / `formalization` / `derived_from`
- 新增命令：`trees evidence <seed> --level L2 --ref doi:...`
- 验收：证据等级可写、可读、可回溯；L3 不等于正确，只进复现队列

### Stage 3 — 撤回传播

- `trees retract <seed|doi> --reason ...`：种子标 `retracted: true`，可信度归零
- 沿 `derived_from` / `bloodline` 下溯，派生树标"待复核"
- 复核通过恢复，否则降权/隔离；**不删除正文**
- 验收：撤回一棵，所有派生节点都被标记

### Stage 4 — 身份与签名

- 本地：`planter` + Git 提交签名（GPG/SSH）
- 发布包增加 `signature` 字段（对 manifest 的签名）
- 公钥指纹写进 manifest；订阅方校验签名 + 哈希
- 验收：改一个字节，校验失败；冒用作者，签名失败

### Stage 5 — 举报 / 审核

- 导入隔离区：`forest/quarantine/`，默认不参与召回
- 举报理由：抄袭 / 注入 / 违法 / 错误；附证据
- 审核结论只影响**可见度与订阅**，不改写历史
- 验收：隔离区种子不会被 recall 命中

### Stage 6 — 版本迁移

- 数据格式带 `format` 版本（发布包已是 `trees-share/1`）
- 旧库升级脚本：字段补齐、默认值、回滚点
- 验收：旧 forest 一键升级，175+ 测试全绿

### Stage 7 — 网络层（Git 联邦）

- `trees remote add <name> <git-url>` / `trees pull <name>` / `trees push <name>`
- 只同步 manifest + 校验通过的内容；冲突走 fork，不覆盖
- 验收：两个本地仓库互相同步一棵树，撤回能传播

### Stage 8 — 区块链（最后，且只做窄用途）

只考虑三件事：

1. **全局身份/公钥登记**（key registry）
2. **时间锚定**（某版本的哈希在某时刻存在）
3. **结算**（若将来真有付费服务）

账本已经是哈希链：上链时只需要把 `events.jsonl` 的 head 定期锚定到链上，
不需要改事件格式。单机链只证明"本机历史未被篡改"，不证明"全网唯一"。

不做：存正文、存种子、存个人数据、自动执行。
风险：隐私、跨境合规、不可篡改与删除义务冲突、吞吐与成本、治理僵局。

---

## 5. 不搞坏电脑的硬约束

- core 只读写本地文件；网络能力只存在于显式的 remote 命令
- 不自动执行导入内容；不 `eval`、不运行种子里的脚本/命令
- 发布包与导入都有大小/数量上限
- 导入先进 `quarantine/`，人工确认后才进主库
- 任何删除先入回收站；撤回只发墓碑，不物理删除
- 每次同步前自动备份 `forest/`（或依赖 git 历史）
- 所有格式带版本号，升级可回滚
