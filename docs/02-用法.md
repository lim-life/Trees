# 用法

> 文中的输出都是示例,具体的数字、日期和排版以你本地的实际输出为准。

---

## 1. 安装

要求:**Node.js >= 20**。CLI 核心零依赖,只用 Node 标准库。

```bash
node -v        # 确认 >= v20
git clone <仓库地址> Trees
cd Trees/tools
npm link       # 让 trees 命令全局可用
trees --help
```

不想全局安装,也可以直接运行:

```bash
node Trees/tools/bin/cli.js --help
```

> 只用 CLI 不需要 `npm install`。只有接入 MCP 时才需要安装唯一的外部依赖 `@modelcontextprotocol/sdk`。

## 2. 从零走一遍

### 2.1 初始化

先用 `--dry-run` 看一下它会做什么,这一步不会改动任何文件:

```bash
trees init --dry-run
```

```
[dry-run] 检测环境:
  ✓ Node v20.11.0
  ✓ Claude Code   (~/.claude.json)
  - Cursor        未检测到
  - Codex         未检测到
[dry-run] 将创建:
  forest/trees/  forest/seeds/  forest/box/
  forest/leaves.log  forest/index.md
[dry-run] 未写入任何文件。
```

确认没问题后,正式执行:

```bash
trees init
```

```
✓ 目录已就绪:/home/you/Trees/forest
✓ Claude Code 已配置(原配置已备份)
完成。
```

`init` 是幂等的,重复执行不会重复创建目录,也不会重复写入配置。

### 2.2 看看空库

```bash
trees ls
```

```
🌱 还没有种子 —— 直接开始做项目吧,做完会自动播种。
```

空库不是错误。退出码为 0,脚本里调用也不会中断。

### 2.3 手动播一颗种子

```bash
trees new "MSYS 路径要用 Unix 格式" --labels Windows,MSYS,bash,路径
```

```
🌰 已播种 seed-0001  MSYS 路径要用 Unix 格式
   文件:forest/seeds/seed-0001.md
   状态:buried
   下一步:trees edit seed-0001 填写 判据 / 做法 / 不适用
```

补全正文:

```bash
trees edit seed-0001
```

用编辑器打开文件,把 `## 判据`、`## 做法`、`## 不适用` 三段填好。三段都是必需的,怎么写见 [01-种子法.md](01-种子法.md)。

### 2.4 浇水

下次真的用上了,而且有效:

```bash
trees water seed-0001 --ok
```

```
💧 seed-0001  watered 0 → 1
   状态:buried → sprouting
   last_watered:2026-10-16
```

用了但没效果:

```bash
trees water seed-0001 --fail
```

```
✗ seed-0001  failed 0 → 1
   状态不变:sprouting
   提示:检查「不适用」是否漏了这次的情境
```

状态升级规则:浇水 1 次 → `sprouting`,≥2 次 → `growing`,≥5 次或经过合成 → `advanced`。

### 2.5 列出种子

```bash
trees ls
```

```
ID         状态        浇水  失败  标题
seed-0001  sprouting   1     1     MSYS 路径要用 Unix 格式
seed-0002  buried      0     0     烧录前先枚举串口,不写死端口号
seed-0003  growing     3     0     多页演示代码先定共享样式,再分页实现
```

### 2.6 总览

```bash
trees status
```

```
🌳 大树   1
🌰 种子   3   (buried 1 / sprouting 1 / growing 1 / advanced 0)
📦 盒子   0
🍂 落叶   12 行

推荐:
  - seed-0002 还没浇过水,下次烧录时试试
```

## 3. 其他常用命令

### 检索

```bash
trees find 路径
```

```
精确命中(标签):
  seed-0001  MSYS 路径要用 Unix 格式            [Windows, MSYS, bash, 路径]
语义相近:
  seed-0004  PowerShell 里路径含空格要加引号     [Windows, PowerShell, 路径]
发散列表(低相关,供联想):
  seed-0002  烧录前先枚举串口,不写死端口号
  seed-0003  多页演示代码先定共享样式,再分页实现
  seed-0007  MSYS 下丢弃输出用 /dev/null
```

发散列表固定列出 3-5 颗低相关的种子,用来打开思路。不用管它也没关系。

### 看详情

```bash
trees show seed-0001
```

会输出完整的 front matter 和正文,内容和 `forest/seeds/seed-0001.md` 一致。

| `trees plant-branch <s-XXXXXXXX>` | 旁支单独播种 |
| `trees recycle <s-XXXXXXXX>` | 旁支回收（休眠） |
| `trees init [--dry-run]` | 检测环境 + 配置 + 建目录 |
| `trees uninstall` | 卸载 |
| `trees new "<标题>" --labels a,b` | 手动新建种子 |
| `trees ls` | 列出种子 |

| `trees plant --dir <目录>` | 批量提取 |

| `trees find <关键词>` | 检索(含发散列表) |

## 4. 三种起步方式

| 方式 | 命令 | 适合 |
|---|---|---|
| 空手开局 | 直接做项目 | 新用户(推荐) |
| 批量提取 | `trees plant --dir <路径>` | 手上已有笔记或旧项目 |
| 种子包导入 | `trees import <包.zip>` | 想快速起步 |

### 空手开局

什么都不用准备,`init` 之后直接开始做项目。会话结束时会提取新种子并写入,没有复用价值的杂事只在 `leaves.log` 记一行。

### 批量提取

```bash
trees plant --dir ~/notes/嵌入式
```

```
扫描 23 个文件...
🌰 播种 6 颗   seed-0008 ~ seed-0013
🍂 落叶 17 条  已记入 leaves.log
```

提取出来的种子都是 `buried` 状态。建议逐颗 `trees show` 检查一遍,重点看「不适用」有没有写空。

### 种子包导入

```bash
trees import 嵌入式入门.zip
```

```
导入 10 颗种子
  origin: external   confidence: 0.5
连续验证成功 3 次后 confidence 升到 1.0
```

导入的种子先按半权重对待。要验证它们,就在实际使用后 `trees water <id> --ok`。

分享自己的种子:

```bash
trees export hand-sword-radar -o hand-sword-radar.zip
```

## 5. 数据存在哪

```
forest/
├── trees/<tree-id>.md    大树
├── seeds/<seed-id>.md    种子
├── box/<seed-id>.md      入盒的种子
├── leaves.log            落叶
└── index.md
```

所有数据都是纯文本 Markdown,可以直接用编辑器打开和修改。

### 换目录:TREES_HOME

默认使用仓库里的 `forest/`。如果想放到别处,设置 `TREES_HOME` 指向数据目录,也就是包含 `seeds/`、`trees/` 等子目录的那一层:

```bash
# Linux / macOS / Git Bash
export TREES_HOME=~/my-forest
echo 'export TREES_HOME=~/my-forest' >> ~/.bashrc   # 永久生效
```

```powershell
# PowerShell
$env:TREES_HOME = "D:\my-forest"
[Environment]::SetEnvironmentVariable("TREES_HOME", "D:\my-forest", "User")  # 永久生效
```

把已有数据搬到新目录:

```bash
cp -r Trees/forest ~/my-forest
export TREES_HOME=~/my-forest
trees status      # 确认数量和原来一致
```

### 备份

数据就是一个目录,打包即可:

```bash
tar czf trees-backup-$(date +%F).tar.gz -C "${TREES_HOME:-Trees/forest}" .
```

更推荐用 git 管理,还能看到每颗种子的修改历史:

```bash
cd "$TREES_HOME"
git init && git add . && git commit -m "trees backup"
```

执行 `trees uninstall` 之前,请先备份一次。

## 6. 常见问题

**空库是什么样?**
所有命令都正常退出,不报错,只提示:

```
🌱 还没有种子 —— 直接开始做项目吧,做完会自动播种。
```

**id 是怎么增长的?**
`seed-0001`、`seed-0002`……全局唯一,自动递增。入盒、召唤、浇水都不会改变 id。合成会产生一个新 id,原种子保留,并标上 `synthesized_into: <新id>`。

**种子入盒了,怎么捞回来?**
6 个月没浇水的种子会移到 `forest/box/`。先看看盒子里有哪些:

```bash
ls "${TREES_HOME:-Trees/forest}/box"
```

然后召唤:

```bash
trees summon seed-0001
```

```
📤 seed-0001 已出盒
   状态恢复为:growing(prev_state)
```

种子会回到入盒前的状态,不会从 `buried` 重来。入盒判据看的是 `last_watered`,所以召唤后用上了,记得 `trees water <id> --ok`。

**能手动入盒吗?**
可以,执行 `trees box <id>`。

**什么算一次浇水?**
用了,而且验证通过,才 `--ok`。只是检索出来看了一眼,不算浇水。

**合成会删掉原来的种子吗?**
不会。原件保留,可以回拆。合成需要人工确认。

**黑夜任务会不会一直烧钱?**
不会。做梦每次最多抽 5 颗、最多跑 10 分钟;所有黑夜任务都可以开关;有月度预算上限,超出后自动停止。
